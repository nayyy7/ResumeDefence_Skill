# Resume Defense Coach

一个基于真实简历与项目材料、支持动态追问和结构化复盘的模拟面试 Agent Skill。

它适用于考研复试、保研/夏令营、科研面试、算法与技术实习面试，以及 AI 产品面试。与固定题库不同，本 Skill 会根据候选人的材料和上一轮回答决定下一步问题，并严格区分“面试”和“复盘”两个阶段。

## 主要能力

- **材料驱动**：围绕用户提供的简历、项目说明、论文、报告或演示材料提问。
- **动态追问**：识别空泛回答、事实冲突、职责不清、无依据指标和术语堆砌，并选择合适的追问方向。
- **多项目覆盖**：为多项目简历分配核心问题，避免只围绕单一项目反复提问。
- **难度递进**：从项目概述逐步深入个人贡献、方法选择、实现细节、技术原理和边界反思。
- **阶段隔离**：面试期间不提示答案、不纠错、不打分；结束后统一进行复盘。
- **证据约束**：不编造职责、数据、指标、实验结果或项目成果；信息不足时明确标记待确认内容。
- **结构化评估**：按 10 个能力维度给出有依据的评分、改进建议和训练计划。

## 工作流程

```text
读取简历与项目材料
        ↓
提取事实、疑点与待确认信息
        ↓
建立隐藏的项目覆盖与问题计划
        ↓
一次提出一个核心问题
        ↓
根据回答追问或切换主题
        ↓
结束面试并逐题复盘
        ↓
输出优化回答与训练计划
```

面试深度通常按以下阶段推进：

```text
PROJECT_OVERVIEW
  → PERSONAL_CONTRIBUTION
  → METHOD_REASONING
  → IMPLEMENTATION
  → TECHNICAL_DEPTH
  → CHALLENGE
```

这些阶段用于控制整体节奏，并不是固定题目清单；自然追问可以改变局部顺序。

## 快速开始

### 1. 安装 Skill

将 [`resume-defense-coach`](./resume-defense-coach/) 整个目录复制到支持 Agent Skill 的客户端或项目的 Skill 目录中。必须保持目录内部的相对路径不变，因为 `SKILL.md` 会按需读取 `references/`、`templates/`、`examples/` 和 `evals/` 中的文件。

### 2. 准备材料

至少提供一份能够支撑提问的真实材料，例如：

- 简历中的项目经历；
- 项目 README、实验记录或课程报告；
- 论文、研究计划或答辩材料；
- 岗位、学校、专业或研究方向说明。

为了获得更贴合的模拟，可以同时说明：

| 设置 | 示例 | 默认值 |
| --- | --- | --- |
| 面试类型 | 考研复试、科研面试、算法实习 | 根据材料判断 |
| 目标方向 | 计算机视觉、NLP、AI 产品 | 不限定 |
| 难度 | 初级 / 中级 / 高级 | 中级 |
| 核心问题数 | 5、8、10 | 8 |
| 动态追问 | 开启 / 关闭 | 开始前询问 |
| 重点项目 | 只问项目 A | 覆盖主要项目 |

### 3. 启动模拟

```text
请使用 resume-defense-coach，根据我上传的简历进行一轮考研复试模拟。
难度中等，共 8 道核心问题，开启动态追问。面试期间一次只问一个问题，最后统一复盘。
```

也可以直接粘贴项目经历：

```text
下面是我的项目经历。请按技术实习面试的强度连续追问，重点检查我的个人贡献、方法选择和实验依据。

[粘贴真实项目材料]
```

## 交互方式

| 用户表达 | 行为 |
| --- | --- |
| `开始模拟` / `开始面试` | 开始或继续面试 |
| `下一题` | 跳过当前问题，不进行即时点评 |
| `重新回答` | 用新回答替换上一轮回答 |
| `提高难度` / `降低难度` | 调整后续问题深度 |
| `只问某个项目` | 将后续问题聚焦到指定项目 |
| `我不知道` | 记录薄弱点并继续 |
| `结束模拟` / `开始复盘` / `点评` | 立即结束面试并生成复盘 |

## 面试与复盘规则

| 面试阶段 | 复盘阶段 |
| --- | --- |
| 保持面试官角色 | 切换为教练角色 |
| 每轮 1 个核心问题，最多 2 个紧密相关的子问题 | 按重要问题逐题分析 |
| 不提供答案或答题框架 | 提供 grounded 的优化回答 |
| 不即时纠错、不打分 | 指出错误、证据缺口和表达问题 |
| 不公开隐藏的题目与覆盖计划 | 解释评分依据并给出训练计划 |

动态追问开启时，Skill 会优先处理：

1. 材料与回答冲突；
2. 个人职责不清；
3. 效果数据缺少证据；
4. 关键技术概念错误；
5. 回答空泛或没有真正回答问题；
6. 方法选择缺少理由；
7. 缺少替代方案、取舍、限制或失败分析；
8. 需要进一步提高技术深度；
9. 应切换到尚未覆盖的项目或能力维度。

关闭动态追问时，每个核心问题回答完后会直接进入下一题；发现的问题只记录在内部，并在最终复盘中统一说明。

## 评分维度

最终复盘采用 1–5 分锚定评分。没有获得足够证据的维度会标记为“未充分评估”，不会凭感觉补分。

| 维度 | 关注点 |
| --- | --- |
| 项目动机与问题理解 | 是否理解项目为何存在、解决什么问题 |
| 个人贡献与项目所有权 | 能否区分个人工作和团队成果 |
| 技术准确性 | 概念、原理和因果关系是否正确 |
| 方法选择与取舍 | 是否理解方案选择、替代方案和代价 |
| 实验、指标与证据意识 | 数据、基线、指标和结论是否有依据 |
| 限制与失败认知 | 是否理解边界、失败案例和改进方向 |
| 逻辑结构 | 回答是否有清晰层次 |
| 表达清晰度 | 是否准确、简洁、适合口头表达 |
| 追问应对能力 | 能否在压力下保持一致和深入 |
| 领域理解与未来思考 | 是否理解领域背景及下一步方向 |

## 事实约束

Skill 将信息分为三类：

1. **明确事实**：用户材料中直接出现的信息；
2. **用户口述事实**：用户在面试回答中补充的信息；
3. **待确认推测**：从上下文推断、但无法视为事实的信息。

以下内容不得被静默编造：个人职责、团队规模、数据集规模、模型与参数、准确率/召回率等指标、基线方案、访谈数量、上线状态、创新成果。需要这些信息但材料不足时，复盘会使用类似 `[请补充实际评测指标]` 的占位提示。

## 文件职责

- [`SKILL.md`](./resume-defense-coach/SKILL.md)：定义适用场景、输入、状态流转、问答约束、复盘流程和质量检查。
- [`question-taxonomy.md`](./resume-defense-coach/references/question-taxonomy.md)：提供规划问题覆盖面时使用的能力分类。
- [`follow-up-strategies.md`](./resume-defense-coach/references/follow-up-strategies.md)：规定回答分析、追问优先级和停止深挖的条件。
- [`scoring-rubric.md`](./resume-defense-coach/references/scoring-rubric.md)：仅在复盘阶段读取，用于避免主观评分。
- [`interview-protocol.md`](./resume-defense-coach/references/interview-protocol.md)：约束面试行为和阶段切换。
- [`project-knowledge-map.md`](./resume-defense-coach/templates/project-knowledge-map.md)：整理项目事实、疑点和问题覆盖计划。
- [`interview-review-report.md`](./resume-defense-coach/templates/interview-review-report.md)：统一最终报告结构。
- [`eval-cases.md`](./resume-defense-coach/evals/eval-cases.md)：验证触发边界、单题数量、深度递进、多项目覆盖和追问开关。

## 验证与维护

这是一个纯文本 Skill，不依赖运行时、数据库或第三方包。修改后至少执行以下检查：

1. 确认 `SKILL.md` 中列出的必需文件全部存在；
2. 使用 `examples/sample-resume.md` 完成一次从材料分析到复盘的完整模拟；
3. 对照 `evals/eval-cases.md` 检查正向触发、不应触发和边界案例；
4. 确认一次只提出一个核心问题，且子问题不超过两个；
5. 确认面试期间没有提前评分、纠错或泄露参考答案；
6. 确认复盘中的项目事实都能追溯到用户材料或用户回答；
7. 提交前检查暂存区，确保没有 AI 工具配置、会话文件或本地索引。

## 当前限制

- 没有图形界面、账户系统或跨会话学习档案；
- 不支持语音面试和真实答题时长统计；
- 不会自动连接招聘网站、学校题库或外部事实数据库；
- 纯 Skill 版本不包含 RAG，无法自动回查超长原始材料中的全部证据；
- 追问和点评质量仍受底层模型能力影响；
- 评分用于训练反馈，不代表真实录取或招聘结果。

## 版本说明

当前内容对应 **V1.1**，主要包含：

- 单轮核心问题与子问题数量限制；
- 从项目概述到技术深度的阶段递进；
- 多项目核心问题覆盖计划；
- 可开启或关闭的动态追问模式。
